# crates/aion-storage — Content-Addressed Model/Artifact Storage

Content addressing for model manifests (weights/tokenizer/config/license CIDs per `docs/PROTOCOL.md`) and integrity verification, per Phase 6 of `docs/ROADMAP.md`.

**Status: real implementation (local half only), milestone 31.** `cargo test -p aion-storage` → 12/12 passing:

- `content_id.rs` — `compute_cid(data: &[u8]) -> Cid` produces a **real, IPFS-compatible CIDv1** (raw codec, SHA2-256 multihash) using the same `cid`/`multihash` crates the wider Rust IPFS/libp2p ecosystem uses (already a transitive dependency via `crates/aion-p2p`'s `libp2p`), not a hand-rolled encoding — per `AGENTS.md`'s "no hand-rolled cryptography" rule, and because CID's multibase/multicodec framing is a real interoperability surface. One test pins a golden value: the exact CID string a real IPFS node computes for a specific input with `--cid-version 1 --raw-leaves` (`bafkreid3y7pm2css2xvjn3lhkdwrlo4tun3usglril7uxcb44otza5mkye` for `b"hello aion"`), independently reproducible by any correct CIDv1/raw/sha256 implementation — proof of genuine protocol compatibility, not just an internally-consistent invented scheme.
- `store.rs` — `ContentStore`, a real disk-backed content-addressed store: `put` writes a blob under a filename derived from its own CID, `get` **re-derives the CID from the bytes actually read back off disk** and returns `StorageError::IntegrityMismatch` rather than silently handing back corrupted/tampered content under a CID that no longer describes it. This is the "integrity verification" the crate's original README stub named as in-scope, now real rather than aspirational — one test directly corrupts a stored file's on-disk bytes (bypassing the store's own `put`) and confirms `get` detects and rejects it instead of returning the wrong bytes. Also tested: put/get round-tripping, content-addressing determinism (identical bytes → identical CID, put is idempotent), distinct content living under distinct CIDs, `NotFound` on an unknown CID, and lazily creating the store's root directory on first open. `disk_usage_bytes()` (milestone 31) sums each stored file's real on-disk size — a genuine filesystem measurement, not an estimate or a separately-tracked counter that could drift — for callers that need to know actual current usage (e.g. `crates/aion-node`'s resource-cap gating).

Honest scope note: this is the **local** half of the crate's eventual scope only. No peer seeding/network distribution (the Bitswap-equivalent half of the original README stub) exists here — that needs a real multi-host network to build meaningfully against, which this dev container doesn't have (the same reasoning already documented for `crates/aion-p2p`'s NAT-traversal testing). No sharded directory layout either (a real large-scale store would likely shard by CID prefix to avoid one huge flat directory) — not needed at the scale these tests run at, and not built ahead of an actual need.

**Not yet done:** this crate's other two natural callers, both wired in as of milestones 30-31 — `crates/aion-protocol`'s `ModelManifest::with_computed_cids` (real CIDs, replacing hand-typed placeholder strings) and `crates/aion-node`'s `CappedContentStore` (gating `put` through `ResourceCaps::max_storage_mb`) — so what remains is genuinely just the network-distribution half described above.
