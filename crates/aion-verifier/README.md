# crates/aion-verifier — Verification Tiers L0-L6

Implements the tiers from `docs/VERIFICATION.md` / `docs/adr/0003-verification-tiering.md`. Produces `VerificationConfidence` for `docs/POIG-SPEC.md`.

**Status: real implementation (partial), milestone 14.** `cargo test -p aion-verifier` → 40/40 passing:

- `tier.rs` — the L0-L6 base-confidence table and adaptive verification-rate function, ported from `simulations/poig_sim/poig_sim/verification.py` (that Python module is the validated reference this crate must not silently diverge from — one test pins the confidence table values directly against it). Confirms L0 is never reward-eligible, the verification-rate floor is never zero even for a perfect reputation, and high-value jobs force a high check rate regardless of reputation.
- `commitment.rs` — L1 tier: a thin, tier-aware wrapper over `aion_crypto::commit_reveal` (the actual cryptographic primitive lives there; this module just maps its result into `VerificationConfidence`).
- `replicated.rs` — L2 tier: clusters N workers' results for the same job by mutual numeric tolerance and returns the largest cluster as consensus, with outliers flagged separately. Distinguishes "numerical nondeterminism" (small relative difference, e.g. hardware/kernel floating-point variance — not flagged) from "diverging/wrong result" (an outlier — flagged, but per `docs/protocol/SLASHING-SPEC.md` outlier status alone is explicitly NOT sufficient grounds for a slash; this module only identifies divergence, it does not decide fault).
- `deterministic.rs` — L3 tier: a **real, working** deterministic-execution harness. `execute_deterministic` actually compiles and runs a WASM module using `wasmi` (a pure-Rust, interpreter-only engine — deliberately not JIT-based, so there's no native-codegen variance across CPU architectures to worry about, which is exactly the class of nondeterminism a "restricted hardware pool" tier exists to eliminate). `verify_deterministic_replication` independently re-executes the same module N times and requires EXACT agreement — unlike L2, there is no tolerance band, since L3's whole premise is a sandbox restrictive enough that no legitimate divergence should remain. **Honestly scoped**: no real AI/ML inference runs here — that needs `crates/aion-runtime` (Phase 4), which needs a GPU this dev container doesn't have. The toy WASM function under test is a stand-in workload; the harness mechanics (compile, execute, compare-for-exact-agreement) are real and would apply to whatever workload eventually runs inside the sandbox.
- `dispute.rs` — L4 tier: the optimistic commit → challenge-window → dispute/undisputed → resolved **state machine**, with the "cheap by default" property enforced directly (confidence is zero while a dispute is pending, full L4 confidence once undisputed or once disputed-but-not-proven, zero if fraud is proven). **Honestly scoped**: this is the state machine only — it does NOT implement bisection re-execution/arbitration (narrowing an interactive dispute down to the exact wrong computation step), which needs a real job-execution pipeline to bisect over (Phase 4, not built yet). A caller (a future `services/verifier`) supplies the dispute verdict from outside; this module doesn't produce one.
- `quorum.rs` — L6 tier: commit/reveal weighted multi-validator quorum, ported from `simulations/poig_sim/poig_sim/quorum.py` — but using **real cryptographic commit/reveal** (`aion_crypto::commit_reveal`, SHA-256 via the audited `sha2` crate) instead of that module's simplified string-concat hash, an improvement possible because `aion-crypto` now exists as a real dependency. Carries over the honestly-documented residual risk: a **minority** colluding validator cluster cannot flip a quorum outcome, but a **majority** colluding cluster *can* — no quorum-weighting scheme can prevent that by construction, and the test suite proves both directions rather than only the flattering one.

**Not yet done:** the actual bisection arbitration protocol behind L4 (see `dispute.rs`'s scope note above), L5 (ZKML, out of scope until the Phase 11 proof-of-concept), real AI/ML workloads inside L3's sandbox (needs Phase 4's execution pipeline). No wiring yet into `crates/aion-node` or a real job-execution pipeline (neither exists yet either).
