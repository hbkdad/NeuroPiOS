## Milestone 12 changes (this update)

- **Resolved** the previously-open 3-node relayed Kademlia discovery bug documented in `crates/aion-p2p/README.md` since milestone 4 (`peer C discovers peer A via peer B, without ever dialing A directly` — the concrete Phase 3 MVP exit criterion "three machines discover each other"). Used `RUST_LOG=libp2p_kad=trace,libp2p_swarm=debug` protocol-level tracing, which milestone 9's write-up had identified as the necessary next step once source-reading alone was exhausted. Trace showed B genuinely computing and queuing the correct FIND_NODE response for C, but the underlying connection being torn down via `KeepAliveTimeout` ~90ms later — before C received it. Root cause: `libp2p_swarm::Config`'s `idle_connection_timeout` defaults to `Duration::ZERO`, so a connection closes the instant no behaviour handler reports pending work, racing an in-flight-but-not-yet-flushed protocol response. Fixed with `.with_swarm_config(|cfg| cfg.with_idle_connection_timeout(Duration::from_secs(30)))` in `build_swarm_with_limits`. Verified via: (1) re-running the same trace after the fix, showing `success: 2, failure: 0` and C's routing table genuinely containing A; (2) a new committed regression test, `tests/kademlia_multi_hop_discovery.rs`, passing cleanly across 5 repeated runs (not a one-off).
- Total test count: 110 (25 Python + 85 Rust), all passing, clippy-clean, fmt-clean.

## Milestone 13 changes (this update)

- `simulations/poig_sim`: added `poig_sim/dispute_economics.py` and `tests/test_griefing.py`, giving `docs/security/ECONOMIC-ATTACKS.md`'s "Griefing" row real (partial) simulation coverage — the first new attack scenario added since milestone 8, and the first to build directly on the L4 dispute state machine (`crates/aion-verifier/src/dispute.rs`, milestone 11) rather than only the earlier verification tiers. Honestly scoped: covers the direct capital cost only, not latency/opportunity-cost griefing damage (a worker tied up in a dispute loses real time even when they win, independent of the bond split) — documented as unmodeled, not hidden; also documents that a 0% worker-compensation split leaves the griefed worker with no direct payout at all. 6 new tests.

## Milestone 14 changes (this update)

- `crates/aion-verifier`: added `deterministic.rs` (L3 tier) — a REAL, working deterministic-execution harness, not modeled abstractly like `tier.rs`. `execute_deterministic` compiles and runs an actual WASM module via `wasmi` (a pure-Rust, interpreter-only engine, chosen specifically because it has no JIT/native-codegen path and therefore no per-CPU-architecture codegen variance — exactly the class of nondeterminism a "restricted hardware pool" tier exists to eliminate, per `docs/VERIFICATION.md`). `verify_deterministic_replication` independently re-executes the same module N times (fresh `Engine`/`Store` each time, no shared state) and requires EXACT byte-for-byte agreement — a deliberate design contrast with L2's `replicated.rs`, which tolerates small numeric divergence as legitimate hardware nondeterminism: L3's whole premise is a sandbox restrictive enough that no such legitimate divergence should remain, so here any divergence at all is itself the fraud/tamper signal. Honestly scoped: no real AI/ML inference runs inside the sandbox — that needs `crates/aion-runtime` (Phase 4), which needs a GPU this dev container doesn't have — the WASM function under test is a toy stand-in workload, but the harness mechanics (compile, isolate, execute, compare-for-exact-agreement) are real. 9 new tests, including a genuine WASM trap surfaced as a typed error (not a panic) and a hand-constructed tampered-replica case proving divergence is flagged, not silently averaged.
- Total test count: 125 (31 Python + 94 Rust), all passing, clippy-clean, fmt-clean.

## Milestone 15 changes (this update)

- `crates/aion-p2p`: added real AutoNAT reachability detection (`autonat::Behaviour`, wired into `AionBehaviour`). A single `autonat::Behaviour` acts as both client (asks a peer to dial it back, to learn whether its own address is publicly reachable) and server (performs that dial-back for others) — the library's own dual-role design, not an AION-specific simplification. `default_autonat_config` keeps the production-correct `only_global_ips: true` (a private/loopback address must never count as evidence of public reachability); a new `build_swarm_with_limits_and_autonat_config` entry point lets tests override that where loopback is the only address family available, without weakening the default every other caller gets. New `tests/autonat_reachability.rs` proves the real wire protocol: peer B asks peer A to dial back, A genuinely dials B's advertised loopback address and succeeds, and B's `nat_status()` transitions from `Unknown` to `Public(addr)` — a real request/response exchange over `/libp2p/autonat/1.0.0`, verified stable across 5 repeated runs, not a stubbed status flip. Honestly scoped: this is reachability DETECTION only — it tells a node whether it's publicly reachable, but does nothing to fix it if not. Circuit relay (the actual NAT-traversal transport) remains unimplemented; that's a larger, separate piece of work (relay-server behaviour plus relay-client TRANSPORT wiring, not just another behaviour) left for a future milestone.
- Total test count: 126 (31 Python + 95 Rust), all passing, clippy-clean, fmt-clean.

## Milestone 16 changes (this update)

- `crates/aion-p2p`: added real circuit relay (`relay::Behaviour` for the relay-server role, `relay::client::Behaviour` for the relay-client role), the actual NAT-traversal TRANSPORT behind milestone 15's AutoNAT detection-only capability. Every node gets both roles by default (no free-riders, same policy already applied to Kademlia's forced server mode). Required a genuine `SwarmBuilder` transport-level change (`.with_relay_client(noise::Config::new, yamux::Config::default)`, which also changes the `with_behaviour` closure's signature to receive the relay-client behaviour as a second argument) — this is meaningfully different from every other behaviour added so far, which only needed a `NetworkBehaviour` struct field. New `tests/circuit_relay.rs` proves the real 3-node case end-to-end: relay node R, peer A (which reserves a relayed listen address through R via a real reservation protocol exchange), and peer C (which dials ONLY an address naming R — `R_addr/p2p/R_peer_id/p2p-circuit/p2p/A_peer_id` — never learning or using A's direct address anywhere in the test) end up genuinely, end-to-end-authenticated connected. Hit and root-caused one real protocol requirement along the way: a relay's reservation response must include at least one of the relay's own confirmed external addresses (`ReserveError::Protocol(NoAddressesInReservation)` otherwise) — on loopback, where `only_global_ips: true` correctly prevents AutoNAT from confirming that automatically, the test bridges the gap with an explicit `swarm_r.add_external_address(r_addr)`, documented in the test as a test-environment necessity, not something a real relay operator would need to do by hand. Verified stable across 5 repeated runs before committing, the same discipline applied to every other network-timing-sensitive test in this crate.
- Total test count: 127 (31 Python + 96 Rust), all passing, clippy-clean, fmt-clean.

## Milestone 17 changes (this update)

Revised to floor connection limits at 1 rather than 0, preserving both the existing test's correct behavior and the new integration's actual safety value. New `tests/resource_caps_connection_limits.rs` proves the derived cap is genuinely ENFORCED end-to-end (a freshly-bootstrapped node accepts one inbound connection and rejects a second), not just correct in isolation — verified stable across 5 repeated runs.

## Definition of MVP (unchanged from brief, restated for tracking)

Three machines discover each other; a requester creates a signed job; a worker executes it; another node verifies it; the model artifact is retrievable by content address; all messages are authenticated; a simulated/testnet reward settles; the dashboard shows real telemetry; bad results can be challenged; a job cannot be paid twice.
